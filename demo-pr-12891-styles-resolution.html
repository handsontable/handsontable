PR #12891 — handsontable/styles/*.css resolution fallthrough

Before the fix, the docs Vite plugin returned undefined for handsontable/styles/*.css imports whenever handsontable/styles/ (gitignored build output) was not built. Vite then resolved the import through pnpm's virtual store to the published npm package, so dev.handsontable.com could serve stale theme CSS. After the fix, the import always resolves to a local monorepo file — the built styles/ output, or the source CSS in src/themes/static/css/theme/.

What this page shows: the same grid twice, differing only in where ht-theme-main CSS comes from. How to verify the fix on the docs dev server

1. On a branch containing the fix, make sure handsontable/styles/ does not exist (fresh clone, or rm -rf handsontable/styles). 2. Run npm run dev in docs/ and open a page whose example imports theme CSS, e.g. /javascript-data-grid/theme-customization/. 3. In DevTools → Network, the theme stylesheet must load from an /@fs/…/handsontable/src/themes/static/css/theme/ht-theme-main.css URL (or …/handsontable/styles/… after a build) — never from node_modules/.pnpm/handsontable@….
