Date filters: exclusive Before/After + new Or-equal conditions (DEV-389 / PR #12473)

Version: Released v18.0.0 CDN PR Build local dist/
How to test (both date columns behave the same; "Sold on" is date, "Registered on" is intl-date):
  1. Exclusive Before: open the "Sold on" dropdown → Filter by condition → Before → type 2019-10-24 → OK. Expected: 3 rows (both 10/24/19 boundary rows are excluded). Before the fix the boundary rows stayed (5 rows).
  2. Exclusive After: After → 2019-10-24 → OK. Expected: 3 rows (10/25/19, 11/2/19, 1/10/20).
  3. Before or equal to: same input 2019-10-24 → OK. Expected: 5 rows (boundary included). "After or equal to" → also 5 rows.
  4. Reset with Filter by condition → None, or reload the page.
This page loads dist/handsontable.full.js — run npm run build --prefix handsontable first, then serve the handsontable/ directory, e.g. python3 -m http.server 8767 --directory handsontable.
Known issue (reproduces here AND on released docs, dev + prod): the filter input only understands strict ISO YYYY-MM-DD. Type the date the way the cell displays it, e.g. 10/24/2019 or 10/24/19 → OK. Result: 0 rows ("No results" — every row is rejected because parseToLocalDate() returns null for non-ISO input, and the free-text filter input is not a date picker; the inputType: 'date' condition descriptor is not consumed by the menu UI).
