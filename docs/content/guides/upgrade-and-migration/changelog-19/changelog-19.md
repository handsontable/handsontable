#### Added
- **Breaking change**: Added treegrid accessibility to the NestedRows plugin: tree attributes on rows, Ctrl/Cmd+arrow keys on a row header to expand, collapse, or move to the parent row, and screen reader announcements. On a row header, Ctrl/Cmd+arrow keys no longer jump to the edge of the row, and Enter no longer toggles while an overlay covers the grid. [#13759](https://github.com/handsontable/handsontable/pull/13759)
- **Breaking change**: The [`Loading`](@/api/loading.md) plugin now needs the [`Dialog`](@/api/dialog.md) plugin registered: `new Handsontable()` throws an error without it, where the loading overlay used to show nothing. Register `Dialog` alongside `Loading`. Added `dist/manifest.json` to the package: a list of every feature, the license token that names it, and the features it needs. [#14094](https://github.com/handsontable/handsontable/pull/14094)
- Added the [`FormulaBuilder`](@/api/formulaBuilder.md) plugin: a formula bar, an inline formula editor with colored references, cell/range/header reference picking, autocomplete, function help, and formula error indicators. DragToScroll no longer starts auto-scrolling on a mouse press that an earlier listener stopped with `stopImmediatePropagation()`, and the autocomplete, dropdown, and multiselect cell arrows ignore such a press too. [#13172](https://github.com/handsontable/handsontable/pull/13172)
- Added the [`preserveTextValue`](@/api/options.md#preservetextvalue) cell meta option that makes the [`Formulas`](@/api/formulas.md) plugin pass values of `text`-type cells to the calculation engine as strings, preserving leading zeros of number-like values. Aligning the escaping across every write path also changed how `loadData()`, `updateData()`, `updateSettings()`, and `setSourceDataAtCell()` feed `date`-type cells to the engine: non-ISO date-like values (for example `'123'`, `'12:30'`, or `'TRUE'`) now reach the engine as text instead of a number, a time fraction, or a boolean, a `type` set only through the `cells()` function now applies on those paths, and those paths now call the `cells()` function and the `beforeGetCellMeta` and `afterGetCellMeta` hooks once per non-formula text cell. The same work fixes the plugin addressing the wrong engine row from `setSourceDataAtCell()` on a sorted or moved grid, writing `#REF!` over a formula whose target still existed and reading a cell's `valueGetter` from the wrong row or column when detaching a row with the `NestedRows` plugin, and reading the autofill source cell's configuration from another cell when rows or columns were trimmed or moved. [#13213](https://github.com/handsontable/handsontable/pull/13213)
- Added a searchable matrix of which configuration levels each option takes effect at, and the same information to every option in the API reference. [#13305](https://github.com/handsontable/handsontable/pull/13305)
- Added the [`clearManualSizes()`](@/api/manualRowResize.md#clearmanualsizes) method to the [`ManualRowResize`](@/api/manualRowResize.md) and [`ManualColumnResize`](@/api/manualColumnResize.md) plugins, and the [`clearManualSize()`](@/api/manualRowResize.md#clearmanualsize) method to `ManualRowResize`, which `ManualColumnResize` already had. They discard the sizes stored by manual resizing, for one row or column or for all of them. [#13307](https://github.com/handsontable/handsontable/pull/13307)
- Added the [`textExtractor`](@/api/options.md#textextractor) option, which writes column and row headers to an exported file, and column headers to the clipboard, as the text the grid displays instead of their raw HTML. [#13308](https://github.com/handsontable/handsontable/pull/13308)
- Added the [`renderMode`](@/api/options.md#rendermode) option, which lets a grid, column, or cell skip repainting cells that did not change since their last render, together with the [`markCellChanged()`](@/api/core.md#markcellchanged) and [`markAllCellsChanged()`](@/api/core.md#markallcellschanged) methods, and made the selection pass update only the cells whose selection state changed. Under `'onChange'`, a vertical scroll paints only the rows that enter the rendered area; with merged cells, the cells of the merged blocks repaint too. [#13384](https://github.com/handsontable/handsontable/pull/13384)
- Added the [`SheetsBar`](@/api/sheetsBar.md) plugin — a tab bar for switching between sheets of a multi-sheet workbook — and the [`getManualSize()`](@/api/manualColumnResize.md#getmanualsize), [`getManualSizes()`](@/api/manualColumnResize.md#getmanualsizes), and [`setManualSizes()`](@/api/manualColumnResize.md#setmanualsizes) methods to the [`ManualColumnResize`](@/api/manualColumnResize.md) and [`ManualRowResize`](@/api/manualRowResize.md) plugins. [#13409](https://github.com/handsontable/handsontable/pull/13409)
- Added the [`autoLink`](@/api/options.md#autolink) option, which renders the URLs, email addresses, and phone numbers in cell values as clickable links, with a `strict: false` mode that also links bare domains and email addresses; `formulas.hyperlinks` now also accepts a `{ target, schemes }` object, and the Formulas plugin's `registerShortcuts()` and `unregisterShortcuts()` methods are deprecated no-ops because the Alt+Enter link shortcut is a core grid shortcut. [#13448](https://github.com/handsontable/handsontable/pull/13448)
- Added a `sortFixedRows` option to the [`ColumnSorting`](@/api/columnSorting.md) and [`MultiColumnSorting`](@/api/multiColumnSorting.md) plugins. It defaults to `false`, which keeps the rows frozen by `fixedRowsTop` and `fixedRowsBottom` out of sorting, as in 18.0.0. Set it to `true` to sort the whole dataset, including both frozen areas. The option is grid-level only. [#13456](https://github.com/handsontable/handsontable/pull/13456)
- Added two ways to narrow what the [`Filters`](@/api/filters.md) plugin covers. The new `filterFixedRows` option, set to `false`, keeps the rows frozen by `fixedRowsTop` and `fixedRowsBottom` out of filtering: they are never hidden by a filter, and their values are no longer listed under `Filter by value`. Setting `filters` to `false` for a column in the `columns` option now hides that column's filter controls in its dropdown menu. [#13522](https://github.com/handsontable/handsontable/pull/13522)
- Added the [`ImportFile`](@/api/importFile.md) plugin, which loads an `.xlsx` workbook into the grid through the ExcelJS engine: cell values and inferred types with their number, date, and time formats, dropdown sources, formulas, merged cells, frozen panes, hidden rows and columns, column widths and row heights, read-only cells from sheet protection, comments, nested headers, and, with `importStyles`, alignment, font, fill, and borders. Features the engine cannot read are reported in one console warning per call. The [`ExportFile`](@/api/exportFile.md) plugin's XLSX writer now shares the same engine adapter: date and time cells export the Excel number format derived from their `dateFormat` and `timeFormat` options (a cell using the default options and the default `en-US` locale now writes `mm/dd/yyyy` and `hh:mm AM/PM` instead of `mm-dd-yy` and `h:mm:ss`; a date cell follows its `locale`, so `de-DE` writes `dd.mm.yyyy`), formula cells carry their column's number format and a cached result, sheet names are sanitized, `compression: false` writes an uncompressed archive, a formula reference qualified with a sheet name (`Rates!A1`) is written and read back unshifted (a known limitation when the referenced sheet is exported in the same workbook with headers, see the export guide), a rendered cell's font color is exported from the cell itself while a cell outside the viewport is read from its classes only, and a rendered font color inherited from a container-scoped CSS variable is no longer written to the file. `batch()`, `batchRender()`, and `batchExecution()` now resume rendering and execution when the wrapped callback throws, instead of leaving the grid suspended. [#13551](https://github.com/handsontable/handsontable/pull/13551)
- Added the `refetchAfterCreate` option to [`dataProvider`](@/api/options.md#dataprovider). Set it to `false` to skip the automatic `fetchRows` refetch after a successful `onRowsCreate` and apply the server response to the grid yourself, for example to keep a newly inserted row on the current page while the grid is sorted. [#13563](https://github.com/handsontable/handsontable/pull/13563)
- Added the [`filterValueComparator`](@/api/options.md#filtervaluecomparator) option to set a custom order of the values in the Filters plugin's "Filter by value" list, per column or for the whole grid. [#13585](https://github.com/handsontable/handsontable/pull/13585)
- Added the [`getCellDependents()`](@/api/formulas.md#getcelldependents) and [`getCellPrecedents()`](@/api/formulas.md#getcellprecedents) methods to the [`Formulas`](@/api/formulas.md) plugin. [#13594](https://github.com/handsontable/handsontable/pull/13594)
- Added a [`showFormulas()`](@/api/formulas.md#showformulas)/[`hideFormulas()`](@/api/formulas.md#hideformulas) toggle to the [`Formulas`](@/api/formulas.md) plugin, so a formula cell can display its formula text instead of its calculated value, and a `Ctrl`+`` ` `` shortcut that toggles it. [#13611](https://github.com/handsontable/handsontable/pull/13611)
- Added a built-in XLSX engine, so `importFile: true` and `exportFile: true` read and write `.xlsx` files without ExcelJS; `engines: { xlsx: ExcelJS }` keeps working. With no engine configured, the "To Excel" context menu item is shown, `supportsExportFormat('xlsx')` and `supportsImportFormat('xlsx')` return `true`, and an XLSX export or import succeeds; `engines: { xlsx: null }` selects the built-in engine, and a per-call `engine: null` keeps the grid's engine. A non-finite number (`NaN`, `Infinity`) now exports as text. Fixed merged-cell meta left behind and `customBorders` throwing after a `loadData`/`updateData` that shrank the grid, `clearBorders()` leaving a border's meta (and its export) behind while rows were sorted or filtered, an XLSX export freezing extra columns or rows when some were hidden, an empty checkbox exporting as `FALSE`, a cleared `numeric` cell exporting as `0`, an XLSX export downloading `[object Promise]` under Zone.js (Angular), the Formulas plugin losing a validated write when `updateSettings()` or a sheet switch ran in the same task, `removeCellMeta()` throwing for an index past the grid's range (it now removes the key at that physical index, like `setCellMeta()`), an XLSX export writing currency codes such as `#,##0.00USD` that Excel repaired and other applications dropped, and dropping the leading zeros of a zero-padded format, an XLSX export of a right-to-left page writing a left-to-right sheet, a merged range with an empty first cell shifting its row in Apple's viewers, a border restored by undo under a filter or trim not being painted again, the export progress dialog showing empty for a grid inside an iframe, two overlapping imports applying in the order they finished instead of the order they started, an XLSX export with `exportFormulas` writing a formula's error result (such as `#DIV/0!`) as text instead of an error cell, an XLSX export with `exportFormulas` writing another row's formula into a cell when rows were sorted, moved, trimmed, or filtered, an XLSX export writing a currency symbol that imported back as another currency or as a plain number (it now writes the ISO 4217 code), an XLSX export writing `LET` and `LAMBDA` parameter names without Excel's `_xlpm.` prefix, custom borders staying on their old rows after `updateSettings({ trimRows })` or being lost by `trimRow()` followed by `loadData()`, a progressive `customBorders` load landing on the wrong rows after a trim or a filter, and an XLSX export writing a date before 1900 or a date that does not exist as a wrong date serial (it now exports as text). [#13634](https://github.com/handsontable/handsontable/pull/13634)

#### Changed
- **Breaking change**: Changed `colToProp()` and `propToCol()` to return `null` when the column index or property names no column that exists and is visible, instead of returning the passed argument. Both TypeScript declarations widened to include `null`. A property name your data does not use is still returned unchanged, and the `modifyData` hook now receives `null` as its column argument for a numeric property that names no column, with its TypeScript declaration widened to match. [#13330](https://github.com/handsontable/handsontable/pull/13330)
- **Breaking change**: Changed `height: 'auto'` to no longer clip the grid, so the page or the nearest scrolling ancestor scrolls it and its rows stay virtualized. See the migration guide for the other `width` and `height` changes. [#13381](https://github.com/handsontable/handsontable/pull/13381)
- **Breaking change**: The `autocomplete`, `dropdown`, and `handsontable` cell types now default `textEllipsis` to `true`, so a long value stays on a single line and truncates with an ellipsis clear of the dropdown arrow, and `autoRowSize` sizes their rows to one line; set `textEllipsis: false` on the column to restore wrapping. [#13509](https://github.com/handsontable/handsontable/pull/13509)
- **Breaking change**: Changed icons to render as `<i class="ht-icon ht-icon-<name>">` elements driven by `--ht-icon-<name>` CSS variables, and extended the theme `icons` option to accept SVG strings, class lists (for icon fonts such as Tabler), or renderer callbacks (for Material Symbols ligatures). Pseudo-element icon selectors are removed and the Filters condition caption text moved into a `htUISelectCaptionLabel` child. Mirrored icons follow the grid's `layoutDirection` instead of an ancestor's `dir`, and a checkbox on a `-no-icons` bundle shows the theme's box with no tick instead of a native checkbox. The `iconsMap()` theme helper is deprecated in favor of `iconStyles()`; see the 19.0 migration guide. [#13639](https://github.com/handsontable/handsontable/pull/13639)
- **Breaking change**: Changed the TypeScript types of the `filters` option. The object form now accepts only `searchMode` and `filterFixedRows`, and a column's `filters` accepts only a boolean, so a misspelled key, a wrong value, or a per-column object no longer compiles. [#13662](https://github.com/handsontable/handsontable/pull/13662)
- **Breaking change**: Changed how undo and redo work: every action is now one undo step that restores the grid state it started from, so an undo puts values back on the right records after rows or columns were moved, sorted, filtered, or trimmed. Hiding, trimming, resizing, freezing, collapsing, custom borders, comments, cell meta, and the pagination page and page size are now undoable, `batch()`, `batchExecution()`, and the new `runOperation()` method group changes into one step, and the new `undo: { maxHistory }` option caps the history. With `undo: false`, nothing is recorded anymore. [#13672](https://github.com/handsontable/handsontable/pull/13672)
- **Breaking change**: Changed the narrowest width a column can be resized to, in a grid whose headers render the dropdown menu button, from 20px to the icon size plus the cell padding on both sides (32px in Main, 40px in Horizon, 24px in Classic), so the menu button stays inside its own cell. - React: Fixed a bug where a component-based renderer in a frozen row or column left the cell empty in one of the two tables the grid draws it in, which made the frozen area stop lining up with the rest of the rows. [#9063](https://github.com/handsontable/handsontable/issues/9063)
- Angular: Fixed a bug where the grid rendered at zero height when the `height` option was relative (for example `'100%'`) and the `<hot-table>` sat in a parent with a fixed height, which also showed up as the grid disappearing inside a CSS-transformed ancestor. [#13690](https://github.com/handsontable/handsontable/pull/13690)
- Angular: Fixed an error logged on every server request when the grid renders on the server, and an error logged on click after the page hydrates. [#14007](https://github.com/handsontable/handsontable/pull/14007)
- Fixed `customBorders` edges that were not drawn on the first column and the first row after the frozen ones. [#14294](https://github.com/handsontable/handsontable/pull/14294)

[#14376](https://github.com/handsontable/handsontable/pull/14376)
